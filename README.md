# calendar-gas

Read-only Google Calendar digest API for the owner's automations.

Given a date, it answers two questions about the owner's day:

- **Night plan**: is there a kept event starting in the evening
  (default 17:00 or later), and when does the last one end?
- **Work end**: until when do the day's earlier commitments run?

Consumers (e.g. alarm-gas, for the "heading home" announcement) use
this to tell a straight trip home from an evening out — without ever
seeing the calendar itself.

## API

```
GET <exec>?token=<API_TOKEN>[&date=YYYY-MM-DD]
-> {"ok":true,"date":"2026-11-24","hasNightPlan":true,
    "nightPlanEnd":"2026-11-24T12:30:00.000Z",
    "lastWorkEventEnd":"2026-11-24T09:00:00.000Z"}
```

- `date` defaults to today (Asia/Tokyo). Timestamps are ISO 8601 UTC.
- All-day events and events the owner declined never count.
- An event starting before the evening but ending after it (e.g. a
  16:00–18:30 meeting) counts toward `lastWorkEventEnd`, not as a
  night plan.

### Schedule RSS

```
GET <exec>?action=rss&token=<RSS_TOKEN>
-> RSS 2.0 feed of the events from today (Asia/Tokyo) through the
   next 7 days, from both calendars, newest first.
```

- For the owner's own reader, following the social-gas pattern. The
  feed carries event titles — that is its purpose — so it has its own
  `RSS_TOKEN`, separate from `API_TOKEN`, and refuses every request
  while the property is unset or the token mismatches.
- The family calendar is **not** filtered by `EXCLUDE_WORDS` in the
  feed (the owner chose the full family schedule for his own
  reading). Declined events are dropped; all-day events are included.
- Each item's guid pairs the event id with its start, so the same
  instance never reappears as new across fetches.

## Privacy rules

- **Event titles are never returned by the digest API and never
  logged.** The digest response carries only booleans and timestamps.
  (The token-guarded RSS above is the one deliberate exception: it
  exists to carry the owner's own schedule to the owner's reader.)
- Nothing personal is hardcoded: calendar ids, the tokens and the
  family-calendar exclude words live in script properties only.
- Tests use dummy fixtures exclusively (fake calendar ids, generic
  titles). Never paste real calendar content into this repository.

## Script properties

| Key | Meaning |
|---|---|
| `API_TOKEN` | Shared secret for the digest. Generated by running `setup()` once. |
| `RSS_TOKEN` | Shared secret for the RSS feed. Also generated by `setup()`. |
| `MAIN_CALENDAR_ID` | The owner's main calendar id. |
| `FAMILY_CALENDAR_ID` | The shared family calendar id. |
| `EXCLUDE_WORDS` | Comma-separated title words. Family-calendar events whose title contains one are ignored (events belonging to other family members). |
| `EVENING_START_HOUR` | Optional. Default `17`. |
